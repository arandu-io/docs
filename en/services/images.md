<a name="decode-only-after-byte-and-pixel-limits-are-known"></a>
## Decode only after byte and pixel limits are known

The released image component decodes, transforms, and encodes common image data behind typed options. The skeleton does not wire it, so each application connects upload, limits, storage, and delivery itself and proves them together.

<a name="inspect-decode-transform-and-encode-one-image"></a>
## Inspect, decode, transform, and encode one image

Bound upload bytes in the application, lower the manager's pixel ceiling, then orient, crop, choose a released encoder, and request the final bytes with context. The library guards decoded pixels; the application still owns byte and requested-output limits.

```go example
func Thumbnail(ctx context.Context, contents []byte, maxPixels int) ([]byte, error) {
	images := image.NewImageManager().MaxPixels(maxPixels)
	img := images.FromBytes(contents)
	encoded, err := img.Orient().Cover(640, 640).ToJpg().Quality(82).ToBytes(ctx)
	if err != nil {
		return nil, err
	}
	return encoded, nil
}
```

<a name="choose-deterministic-transforms-and-output-metadata"></a>
## Choose deterministic transforms and output metadata

Normalize orientation once, strip unneeded metadata, choose crop or contain behavior explicitly, generate storage keys independently of filenames, and write output through the filesystem adapter only after the entire transform succeeds.

- Bound input bytes before `FromBytes`.
- Set a decoded-pixel ceiling.
- Validate requested output geometry in application code.
- Use JPEG, PNG, or GIF with the standard driver.

<a name="reject-decompression-bombs-and-unsupported-formats"></a>
## Reject decompression bombs and unsupported formats

Malformed headers, unsupported format, excessive pixels, truncated input, encoder failure, and storage failure are separate outcomes. Never fall back to serving the unvalidated original when a transform refuses it.

> [!WARNING]
> Compressed byte size is not a safe memory limit. Enforce the released decoded image ceiling before allocating full pixel buffers and rehearse the chosen limits under concurrent uploads.

<a name="use-real-fixtures-at-every-configured-ceiling"></a>
## Use real fixtures at every configured ceiling

Use tiny valid fixtures, boundary dimensions, one-over-limit pixels, truncated and polyglot data, animated input when unsupported, orientation metadata, transparent pixels, deterministic resize output, encoder failure, and concurrent memory profiling.

- Excessive declared pixels fail before canvas allocation.
- Output dimensions and media type match contract.
- Input and requested-output byte limits are application-tested.
- A failed transform writes no stored object.

<a name="released-image-component-boundary"></a>
## Released image component boundary

`NewImageManager`, `MaxPixels`, FromBytes/FromStream, Orient, Cover, Contain, Resize, Scale, `ToJpg/ToPng/ToGif`, and `ToBytes` form the released standard-driver surface. WebP-like format names are recognized but have no standard encoder and must fail rather than produce mislabeled bytes.

| Surface | Released contract |
| --- | --- |
| `MaxPixels` / `FromBytes` | decode under a pixel ceiling |
| Cover / Contain / Resize | deterministic geometry |
| `ToJpg` / `ToPng` / `ToGif` | released standard encoders |
| `ToBytes` / Dimensions | context-bound output and metadata |
